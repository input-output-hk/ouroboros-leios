# Catalog of Leios Simulations and Models

**Created:** 2026-09-16
**Status:** Draft for review. An adversarial LLM fact-check pass (Opus, 2026-09-16) verified the initial claims against sources; per-row source-level deep dives (see below) then deepened and corrected every entry.
**Provenance:** 🤖 (LLM-generated, pending human review)

This catalog answers the question posed in [#team-leios on 2026-09-16](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1789558993289409?thread_ts=1789558993.289409&cid=C074AHSKJF7): *what network simulators do we currently have available for Leios, and what are their faithfulness to the implementation, status, scope, and performance?* No such summary previously existed (confirmed in that thread). It covers simulators in the strict sense, network-emulation test beds, and analytical/mathematical models — anything that predicts or reproduces Leios behavior short of the production `cardano-node` implementation itself — with emphasis on networking.

Ouroboros Leios ([CIP-0164](https://github.com/cardano-foundation/CIPs/pull/1078)) is a throughput-scaling extension of Ouroboros Praos in which block producers create larger **endorser blocks (EBs)** alongside Praos **ranking blocks (RBs)**; EBs are certified by a stake-weighted voting committee before ledger inclusion. Earlier protocol variants also had **input blocks (IBs)**, since dropped; several artifacts below predate that change, which is the single most important faithfulness caveat in this catalog. Two new node-to-node (N2N) mini-protocols carry Leios traffic: **LeiosNotify** (announcements) and **LeiosFetch** (data retrieval).

Each entry records the four dimensions from the motivating question. "Faithfulness" is assessed against the current protocol design (CIP-0164 Linear Leios) and, where relevant, against the prototype `cardano-node` implementation running on the Leios testnet. Statements are current as of 2026-09-16; repository descriptions were read at that date's `HEAD` of each default branch.

**Deep dives.** Every row has a source-level deep dive in [`leios-simulation-model-catalog/`](./leios-simulation-model-catalog/) — created by reading each artifact's code, documentation, and results (commit-pinned in each file): [01 sim-rs](./leios-simulation-model-catalog/01-sim-rs.md) · [02 Haskell `ols`](./leios-simulation-model-catalog/02-haskell-ols.md) · [03 leios-peernet](./leios-simulation-model-catalog/03-leios-peernet.md) · [04 AUEB reports](./leios-simulation-model-catalog/04-aueb-network-modeling.md) · [05 smol world](./leios-simulation-model-catalog/05-smol-world.md) · [06 Mininet LeiosFetch](./leios-simulation-model-catalog/06-mininet-leiosfetch.md) · [07 Piranha/net-rs](./leios-simulation-model-catalog/07-piranha-net-rs.md) · [08 DeltaQ](./leios-simulation-model-catalog/08-deltaq-models.md) · [09 Markov `linleios`](./leios-simulation-model-catalog/09-markov-linleios.md) · [10 post-CIP mempool](./leios-simulation-model-catalog/10-postcip-mempool-models.md) · [11 formal spec + verifier](./leios-simulation-model-catalog/11-formal-spec-trace-verifier.md) · [12 execution environments](./leios-simulation-model-catalog/12-execution-environments.md).

## Mempool and transaction-cache representations

The memory pool is an expected focus of upcoming study, so it gets its own comparison. Each row summarizes how (and whether) the artifact represents the mempool — admission from the network, caches/compartments, (re-)validation, and drainage into blocks — plus any **TX caches beyond the mempool** and their **residence times** (how long TX bodies stay resident and what evicts them). Rows are filled in as the per-entry deep dives (in [`leios-simulation-model-catalog/`](./leios-simulation-model-catalog/)) complete; unfilled rows carry what is already known and are marked *(pending dive)*.

## Simulators and emulators

### 1. sim-rs — the Rust Leios simulator

**Location:** [`input-output-hk/leios-tools/sim-rs`](https://github.com/input-output-hk/leios-tools/tree/main/sim-rs) (moved from [`ouroboros-leios/sim-rs`](https://github.com/input-output-hk/ouroboros-leios) with per-directory history preserved). Crates: `sim-core`, `sim-cli`, on shared `shared-rs` (consensus behavior-tree engine, `tcp-model`).

**Deep dive:** [leios-simulation-model-catalog/01-sim-rs.md](./leios-simulation-model-catalog/01-sim-rs.md).

**Scope.** The most complete Leios simulator: transactions, mempool (see the [mempool table](#mempool-and-transaction-cache-representations) and dive § 4), IB/EB/vote/RB objects, sharding strategies, attacker behaviors, and the transaction lifecycle end to end. **Seven protocol variants** behind one `leios-variant` enum — `short` (still the shipped default, though outdated), `full`, `full-without-ibs`, `full-with-tx-references`, `linear`, `linear-with-tx-references` (the CIP-0164 track), and the nascent `shared-consensus`. Emits JSONL or CBOR event traces consumed by the analysis notebooks, the web visualizer, and the trace verifier. Configured by shared YAML parameter files ([`data/simulation/config.default.yaml`](https://github.com/input-output-hk/leios-tools/blob/main/data/simulation/config.default.yaml) with JSON schema) and topology files up to the 10,000-node pseudo-mainnet.

**Network faithfulness.** Explicit point-to-point connections with independent per-direction latency and bandwidth; bandwidth on a connection is split equally among *active mini-protocols*, and messages within one mini-protocol serialize. Three transport regimes are dispatched per connection (documented in [`sim-rs/docs/tcp-modelling.md`](https://github.com/input-output-hk/leios-tools/blob/main/sim-rs/docs/tcp-modelling.md)): a **TCP congestion-window model** — a direct port of the Haskell simulator's `ModelTCP.hs`, with slow start (initial window 10 per RFC 6928, 1460-byte segments) and RFC 6298 idle reset — which is **on by default** (`tcp-congestion-control: true` in `config.default.yaml`); a simple latency + fair-bandwidth fallback (delay = size/bandwidth + latency) when that is disabled; and an analytic envelope from `shared-rs/tcp-model` (slow-start ramp, idle reset, and loss modeled as a one-RTO head-of-line stall with additive-increase/multiplicative-decrease recovery), mutually exclusive with the congestion-window model and unused under default configuration. What the default regime genuinely omits: packet loss, retransmission, and delayed ACKs. Mini-protocols are fire-and-forget, not state machines, so pipelining and head-of-line effects of the real N2N multiplexer are out of scope.

**Determinism.** Two engines: the default `actor` engine (tokio actors on a coordinated virtual clock; *not* deterministic; supports attackers) and a `sequential` discrete-event engine (strict timestamp order; deterministic; no attacker support). Both support sharding nodes into parallel groups with conservative message blocking based on minimum inter-shard latencies; configurable clock resolution trades temporal precision for parallelism.

**Status.** The actively maintained simulation (per the ouroboros-leios README and the 2026-09-16 thread). Originally built by Sundae Labs under the 2024 statement of work; now maintained by the testnet/red-team group. Current work: vote-diffusion strategy evaluation (William Wolff, Sept 2026), telemetry and mempool extensions (Aug 2026), time-windowed **network partition scenarios** with a continent-cut generator (Jul 2026), and — the big structural item — the **shared-consensus migration**: retiring `linear_leios.rs` onto the sans-IO `shared-rs/consensus` state machines so sim-rs, net-rs, and Piranha drive one consensus core, with byte-equivalent trace comparison as the acceptance test (TX path wired so far). Adversarial support is three-layered: built-in late-EB/late-TX attack configs, per-node topology flags, and per-node **behavior trees** using the same engine and action vocabulary as Piranha. A `txn_diffusion.sh` script exports diffusion CDFs as ΔQ expressions — a working sim→analytical bridge to entry 8.

**Performance.** Virtual-time execution "as fast as your machine allows," multithreaded; ran the pseudo-mainnet topology family — 10,000 nodes in v1, flagged by its own README as a first cut; the currently recommended `topology-v4-mainnet.yaml` is 2,685 nodes — and Linear Leios workloads up to 1000 transactions per second (TPS) in the 2025 experiment series ([Slack, 2025-07-25](https://input-output-rnd.slack.com/archives/C07C7JTPX1U/p1753475153116689) and the `analysis/sims` notebooks). Trace files grow huge quickly at scale.

**Faithfulness checks available.** Its traces are checked by the Agda-derived trace verifier (entry 11), and it was historically cross-validated against the Haskell simulator (IB-diffusion comparison experiments, 2025).

### 2. Haskell simulation (`ols`)

**Location:** [`ouroboros-leios/simulation/`](https://github.com/input-output-hk/ouroboros-leios/tree/main/simulation). **Deep dive:** [leios-simulation-model-catalog/02-haskell-ols.md](./leios-simulation-model-catalog/02-haskell-ols.md).

**Scope.** Praos block diffusion and Short/Full/**Linear** Leios — Linear was retrofitted (Jul–Aug 2025) by mapping EBs onto the IB machinery, is trace-verifier-checked, but predates later CIP-0164 refinements. Block-level only: **no transactions and no mempool** (payloads are configured byte sizes). Built-in Gtk+ live visualization and PNG frame export; `ols viz` / `ols sim` entry points plus topology conversion/generation utilities and a `report-data` mode that can emit *idealized graph diffusion* as an analytic baseline. Configuration is partly in code — experiments require editing source.

**Faithfulness.** *Structurally* the highest-fidelity simulator in the catalog: built on `io-sim`/`io-classes` (the production node's simulation monad) and `Network.TypedProtocol` (its actual protocol framework), so ChainSync, BlockFetch, and the IB/EB/vote Relay protocol are real typed state machines with genuine window semantics (`RelayBuffer` ticket machinery), multiplexed over a modeled TCP bearer. Its `ModelTCP.hs` (no loss/retransmission) is the origin of sim-rs's default TCP regime, so the two simulators are transport-equivalent by construction. It is also the only artifact that honors the `cleanup-policies` config key: cache residence is enforced by pipeline-arithmetic pruning threads (see the mempool table). *Content*-wise it is frozen at mid-2025: [`simulation/README.md`](https://github.com/input-output-hk/ouroboros-leios/blob/main/simulation/README.md) states it predates the move away from input blocks and is no longer current with the protocol design. The Praos and network visualizations remain useful.

**Status.** Dormant for Leios purposes; superseded by sim-rs.

**Performance.** Slower than sim-rs (single high-fidelity runs; the November 2025 simulation tutorial recorded the team preference for "the faster, multithreaded Rust simulator over the high-fidelity Haskell simulator"). Developed largely by Well-Typed (by commit count: Andrea Vezzosi, Wen Kokke, Duncan Coutts), with IOG's Nicolas Frisby contributing comparably to Coutts.

### 3. leios-peernet (Java / PeerNet)

**Location:** [`input-output-hk/leios-peernet`](https://github.com/input-output-hk/leios-peernet) — a **private** repository (accessible to this effort's token, unlike entry 7's) — with an `analysis/` ingestion pipeline alongside. PeerNet itself is a git submodule (SSH-pinned). **Deep dive:** [leios-simulation-model-catalog/03-leios-peernet.md](./leios-simulation-model-catalog/03-leios-peernet.md).

**Scope.** Block diffusion only — no mempool, no distinction among RB/IB/EB/vote (a single block type), no stochastic block production or sizes. Header-first dissemination with fixed validation delays over **close/random (C/R) overlays** — the exact `CxRy` vocabulary of the AUEB reports (entry 4), with a `Cougar` static-overlay protocol tying the code to that research lineage. The transport is **latency-multiples, not bandwidth**: body wire time = one-way latency × (1 + 2·extra-TCP-trips); a ΔQ-derived size-scaling table exists but its application is commented out at HEAD, so body size affects only the sender-side upload throttle (`LeiosMulti`: one upload at a time, queue served freshest-first among peers not busy downloading — with a globally shared busy table no real node could have). Latency is uniform by default; the referenced real RTT matrices (WonderNetwork 2022, an IOHK-testbed file) are **absent from the repository**. Built on [PeerNet](https://github.com/PeerNet/PeerNet) (Spyros Voulgaris's framework), which also offers EMU (thread-per-protocol) and NET (real socket) modes — unexercised here.

**Faithfulness and performance (as assessed Feb 2025).** Brian W. Bush aligned its configuration with the 100-node reference topology and found: block-arrival latencies roughly 2× the Haskell simulator's (the commented-out size scaling above is a plausible contributor); protocol breakdown between 5 and 10 blocks/s; topology effectively parameterized in code (a static-topology-file initializer exists but is commented out and its data file absent); fewer network/CPU parameters than Haskell/Rust; very poor scaling (hours per run at high block rates); JSON event logging had to be added for analysis — those events feed the repo's MongoDB `analysis/` pipeline. Conclusion at the time: not worth further investment given the Haskell/Rust simulators' RB/IB/EB/vote-level resolution ([assessment](https://input-output-rnd.slack.com/archives/D07TDP6GATF/p1740144145525689), [comparison request](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1740087047992029)). William Wolff's run plots are in a [Drive folder](https://drive.google.com/drive/folders/1FquVrKshA8btSYnmbllg4CvsB98XZTXH).

**Status.** Dormant; last repository update 2025-02-21.

### 4. AUEB network-modeling reports (Kolyvas & Voulgaris)

**Deep dive:** [leios-simulation-model-catalog/04-aueb-network-modeling.md](./leios-simulation-model-catalog/04-aueb-network-modeling.md) — which **revised this entry**: the "in-house built network simulator" is **PeerNet** (TECHREP1 states it), and the reports date from the **Praos-era IOHK–AUEB collaboration** (TECHREP1: February 2021; authors Evangelos Kolyvas and [Spyros Voulgaris](https://acropolis.aueb.gr/~spyros/)). They were *resurfaced* — not newly produced — by Marcin Szamotulski on 2026-05-15 for the Linear Leios "25% avalanche" discussion:

### 5. "smol world" (ouroboros-network PR #5424)

**Location:** [IntersectMBO/ouroboros-network#5424](https://github.com/IntersectMBO/ouroboros-network/pull/5424), branch `mw/hello-smol-world` (Marcin Wójtowicz) — two commits, 2026-08-28 and 2026-08-31; a **new drop, not a long-lived branch**, though comments reference a substantial private corpus (design/mechanics docs, an experiment driver, reviewer rounds) that is not on the branch. **Deep dive:** [leios-simulation-model-catalog/05-smol-world.md](./leios-simulation-model-catalog/05-smol-world.md).

**Scope.** In the author's words: "a discrete-event simulator with realistic transport (loss + RTO [retransmission timeout]) on a faithful small-world topology with per-node egress contention." 1,360 lines of dependency-light Haskell (no io-sim, no typed protocols), fully seeded/deterministic. Transport is **per-flow CUBIC congestion control** with RTO/fast-retransmit, optional SACK/jitter/reordering, and loss from *two* sources — emergent egress-fair-share oversubscription and per-RTT-tier Gilbert–Elliott chains — the deepest transport fidelity in this catalog (self-described as "the model the ΔQ report could not supply"). Protocol content is **Linear Leios EB diffusion** with CIP-0164 constants (announce → body ≤512 kB → closure pull from first announcer; 14-slot cadence; σ_c truncated committee; 0.75 quorum), separating network-secured from voted quorum, plus `simulateBattle` for **rival sibling EBs splitting the committee**. Topology: stratified small-world generator (clusters/regions/continents, log-normal stake, static churn relaxation) with three ΔQ-report-sourced RTT tiers. Its Phase-2 form is a **mempool-alignment model** — see the [mempool table](#mempool-and-transaction-cache-representations).

**Status and use.** A **draft** PR with no reviews or comments and no commits since 2026-08-31 — not yet under review. Nonetheless apparently load-bearing: the Linear Leios stability analysis presented by Marcin Wójtowicz and Karl Knutsson (September 2026) drew on "network simulator results and a theoretical analysis grounded in published BitTorrent research," showing how system stability depends on egress throughput ([high-five](https://input-output-rnd.slack.com/archives/C011H74QZNF/p1788799962666299)). ❓🤖 **SCRUTINY**: that the presentation's simulator is this PR is inferred from authorship and timing, not stated outright; the presentation artifact itself (slides/recording) was not located in this pass. Sebastian Nagel also noted that Marcin W. "just built something similar" to sim-rs and might review it ([#team-leios, 2026-09-14](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1789410308296569?thread_ts=1789389089.010549&cid=C074AHSKJF7)).

**Performance/faithfulness.** Deliberately narrow beyond its niche: one EB (or two rivals) per run, no Praos chain dynamics, no vote transport, no attackers, uniform tx sizes, synthetic topology. As published it is a library with no driver — the experiment harness lives in the author's private corpus.

### 6. Mininet LeiosFetch test bed

**Location:** [ouroboros-leios PR #880](https://github.com/input-output-hk/ouroboros-leios/pull/880) (`nfrisby/april2026-checkpoint`), directory `docs/targeted-design-investigations/mininet-LeiosFetch-test-bed/`. Author: Nicolas Frisby. **Deep dive:** [leios-simulation-model-catalog/06-mininet-leiosfetch.md](./leios-simulation-model-catalog/06-mininet-leiosfetch.md).

**Scope.** An **emulation** (not simulation): a pull-based P2P diffusion protocol for large payloads (12 MB EB closures) runs in real processes with real kernel TCP over [Mininet](http://mininet.org/), each link materialized as a **middlebox host** owning the bottleneck (fq_codel AQM egress shaping; delay on the host legs), inside a privileged Docker container. The protocol is LeiosFetch-shaped: content-addressed manifests, component-level sparse-bitmap requests, chunk cancellation, offer-pipelining credits. The **policy is the model**: a C node embeds pure-Python fetch schedulers — `OnePeerScheduler` (bandwidth floor, catastrophic tail), `FullHedgeScheduler` (hedge everything, cancel duplicates), and the primary `FetchScheduler` (per-peer **BDP probing** → calibrated pipeline depth, rebalancing on throughput signals, thresholded tail hedging, stall-snubbing with exponential backoff). On the 8-source co-injection topology Fetch beats FullHedge on *both* latency (~2.2 s vs ~3.1 s; OnePeer ~10 s) and bandwidth (59.9 vs 96.9 MB; floor 52.7), with an explicit tarpit-adversary analysis — **but the BDP estimator is oracle-stubbed in these runs** (best-case numbers, per `ANALYSIS.md` itself). Companion documents: `PRIOR_ART.md` (hedged requests, bandits, BitTorrent piece selection — the same literature behind entry 5's stability theory), `loss-model-memo.md` (AQM-dominated backbone loss ~10⁻⁵–10⁻⁴; CUBIC throughput set by RTT and loss, not capacity), and unreported `topo-small-world*.json` inputs.

**Faithfulness.** Highest transport realism in the catalog short of real deployment — actual kernel TCP — but the protocol logic is a stylized LeiosFetch, not the `cardano-node` implementation, and topologies are small (e.g., `topo-8-1`).

**Design memos attached.** `IDEA-NeighborhoodFarPeers.md` (with its Appendix's concrete far-peer policy and supporting arithmetic — the output of the "25% avalanche" thread and the AUEB reports) and `IDEA-EbClosureMinimumAge.md`.

**Status.** **Draft** PR, April 2026 checkpoint; discussion active through May 2026.

### 7. Piranha node + cluster (leios-adversarial-tools)

**Location:** `input-output-hk/leios-adversarial-tools` — **private**; not accessible to this catalog's author token ❓🤖 **SCRUTINY**: the private half is characterized from Slack. The public substrate (`net-rs`, `shared-rs`, the behavior-tree spec) has now been read from source. **Deep dive:** [leios-simulation-model-catalog/07-piranha-net-rs.md](./leios-simulation-model-catalog/07-piranha-net-rs.md). The private repo contains `net-node`, `net-cluster`, `net-ui`, and behavior-tree definitions (`behaviours/*.toml`).

**Scope.** A lightweight Rust Cardano/Leios node ("Piranha") built on the public **net-rs** stack (below), deployed as a cluster (PIR0 plus red-team machines PIR1–PIR10; [Lotoski 2026-08-30](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1788082826261799?thread_ts=1788041943.086199&cid=C074AHSKJF7), [Paprocki 2026-09-10](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1789027355690649?thread_ts=1788741781.779759&cid=C074AHSKJF7)) on the **live Leios testnet** by the red team (Christopher Tilt, Krzysztof Paprocki, Dmitry Shtukenberg; infrastructure John Lotoski). It forges blocks, votes, and certifies, but has **no ledger** — it reads nonces, BLS keys, and committee positions from kleioscan/dbsync; mempool capacity 10,000 transactions ("at least in Piranha" — [Shtukenberg via Nagel, 2026-08-12](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1786523419991819?thread_ts=1786468624.278459&cid=C074AHSKJF7)). Behaviors (honest default, or attacks: withholding TX offers, not fetching EB bodies, crafting EBs directly with chosen transactions) are driven by the behavior-tree engine in `shared-rs` ([spec](https://github.com/input-output-hk/leios-tools/tree/main/specs/001-behavior-tree-engine)). Demonstrated the EB Trojan Horse attack against the testnet (Aug 2026).

**As a network simulator.** Dmitry Shtukenberg (2026-09-16): "It can be used as network simulator with light-weight nodes. It can make sense for some kinds of research" — i.e., many cheap protocol-faithful nodes on real networking, between sim-rs's abstractions and full `cardano-node` deployments.

**Faithfulness.** Real N2N wire protocols (it interoperates with prototype `cardano-node`s), real network; *not* faithful in ledger/validation behavior. That gap is partly the point — it is what the red team exploits and probes — but it has also produced *accidental* protocol violations on the testnet (an unintended EB forging and double spends acknowledged in the [Aug 2026 thread](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1787863719890129)), so treat Piranha-sourced traffic as protocol-shaped, not protocol-correct.

**Status.** Active; cluster state (Node/Piranha/Off) is tracked at the bottom of the internal IOG stake dashboard ([Lotoski 2026-08-30](https://input-output-rnd.slack.com/archives/C074AHSKJF7/p1788082826261799?thread_ts=1788041943.086199&cid=C074AHSKJF7)).

**Public substrate: net-rs.** [`leios-tools/net-rs`](https://github.com/input-output-hk/leios-tools/tree/main/net-rs) (~28 kloc) is the reusable, public part: all eight N2N mini-protocols as real state machines with mainnet-vector-tested CBOR codecs and cardano-node-interoperable era wrapping, a QoS multiplexer (Praos priority, Leios weighted fair queuing), and a 4-kloc multi-peer coordinator (tip dedup, RTT-ranked fetch selection with poisoned-measurement skip, quorum-triggered fetch bursts, 1,000-slot offer dedup). It drives the **same `shared-rs` `MempoolState`/`LeiosState`/`PraosState`** that sim-rs is migrating to — fed here by real TxSubmission — and `LeiosStore`'s `TxBodyResolver` hook (mempool answers LeiosFetch requests for EB transactions) is the live realization of EB-closure write-back. All caches are bounded (LeiosStore 100-slot window; see the mempool table). Positioned as "built for network prototyping, simulation, and as a reference design for node implementors."

## Analytical and formal models

### 8. DeltaQ models

One lineage, two distinct artifact families (rows 8a/8b in the tables), applying ΔQ systems development (ΔQSD) — algebraic composition of latency distributions (CDFs) — to Leios. **Deep dive:** [leios-simulation-model-catalog/08-deltaq-models.md](./leios-simulation-model-catalog/08-deltaq-models.md).

**8a — [`delta_q/`](https://github.com/input-output-hk/ouroboros-leios/tree/main/delta_q)** (Roland Kuhn, 2024–25; begun upstream as [`rkuhn/deltaq-rs`](https://github.com/rkuhn/deltaq-rs)): a general-purpose Rust + web-UI (WASM) tool for ΔQSD modeling, extending the published theory with **load analysis** (resource-usage metrics attached to outcomes, propagated with delay-convolution and load-factor scaling), gossip-diffusion operators, and bounded recursion. Used in the 2024–25 phase to model IB diffusion timeliness; its shipped `models.txt` includes ΔQ encodings of AUEB TECHREP1's Cardano model (entry 4), and stored comparison outputs show it was cross-checked against both simulators. sim-rs still exports diffusion traces to it (`txn_diffusion.sh`). **The effort reached a dead end and stopped in February 2025** (final substantive commits: a proposed `STRETCHED` operator, report/Logbook updates); included here for completeness. The 2026 analyses (8b) built on the Haskell `deltaq` stack instead, and its load-analysis capability was never applied to Linear Leios sustained load.

**8b — [`analysis/deltaq/linear-leios/`](https://github.com/input-output-hk/ouroboros-leios/tree/main/analysis/deltaq/linear-leios) and [`analysis/deltaq/improved-leios/`](https://github.com/input-output-hk/ouroboros-leios/tree/main/analysis/deltaq/improved-leios)** (Yves Hauser, 2026): the Linear Leios security/timing analyses. The original ([report](https://github.com/input-output-hk/ouroboros-leios/blob/main/analysis/deltaq/linear-leios/docs/report.md), Jul 2026) grounds a low-complexity ΔQ model in mainnet-measured `applyTx`/`reapplyTx` distributions, a mainnet-fitted stake power law, and Praos random-graph hop blending, concluding EB diffusion completes within L = 14 slots with 97.4% probability under CIP-0164's (1, 4, 7) — the current *analytic* defense of those parameters. It contains an explicit **mempool + TxCache Markov model** (see the mempool table). The **improved report** (Aug 2026, reviewed in PR #1051) fixes three structural bugs, re-derives timings from `block-edf.csv`, and bounds network sensitivity between **Mathis/Reno and CUBIC** congestion-control models (~11× throughput apart at loss 10⁻⁴), with EB-size/loss/π₁ sweeps, a silent-adversary tail case, and Monte Carlo validation — it is the "improved-ΔQ report" whose Praos Table 1 RTTs smol world cites (entry 5). Known limits (stated in the reports): honest-path only, no freshest-first delivery, single-EB rather than sustained load — the load gap smol world positions itself to fill. In the May-2026 avalanche thread, Sebastian Nagel cited Hauser's and Wójtowicz's DeltaQ work as prior art — that work *is* 8b (62 commits by Hauser, contributions by Wójtowicz). Nicolas Henin's related analysis remains unlocated.

### 9. Markovian model of Linear Leios (`linleios`)

[`analysis/markov/`](https://github.com/input-output-hk/ouroboros-leios/tree/main/analysis/markov) (Brian W. Bush, Oct–Nov 2025, Lean 4, property-tested). **Deep dive:** [leios-simulation-model-catalog/09-markov-linleios.md](./leios-simulation-model-catalog/09-markov-linleios.md). Not a sampled simulation but a **forward evolution of the full state-probability distribution** — state = (clock in RB opportunities, RBs forged, EBs certified, hasRb, canCertify), substeps forge-RB / certify / forge-EB / vote — with sub-tolerance states pruned and the discarded mass *reported* (tracked, not silent, approximation). Network and CPU fold into three input probabilities (p_rb, p_eb, p_late); the adversary is **abstaining stake** (never forges or votes) — the mildest adversarial model in the catalog, bounding liveness but not equivocation or withholding. Its sortition/quorum math is the shared ancestor of the ΔQ analyses' (entry 8), so the two are consistent by construction. Outputs: RB/EB/payload efficiencies and the exact distribution of certified-EB counts; four recorded parameter/adversary/network sweeps. Complete and stable since Nov 2025.

### 10. Mempool and constraint models (post-CIP)

[`post-cip/`](https://github.com/input-output-hk/ouroboros-leios/tree/main/post-cip) collects post-CIP modeling by Brian W. Bush (primary; through Feb 2026) with Yves Hauser and William Wolff extending the simulator and constraint model through Sept 2026. **Deep dive:** [leios-simulation-model-catalog/10-postcip-mempool-models.md](./leios-simulation-model-catalog/10-postcip-mempool-models.md). The mempool family is a mutually validating **theory / simulation / measurement triad**: `mempool-model/` (closed forms: logistic RRG diffusion, λ ≈ 4 hops on mainnet; **hypergeometric mempool overlap** in the overburden ξ; the front-running **poisoning law** ≈ 1 − (1 − p_adv)^(λ−1), both slopes simulator-confirmed), `mempool-sim-web/` + `mempool-sim-viz/` (TypeScript DES of tx gossip with adversarial front-running and a stylized Leios EB mode — overflow-driven EBs, coin-flip certification, 2-step EB-tx fetch with an `--no-eb-tx-cache` toggle — documented by a per-mechanism model-card of simplifications), and `mempool-measurements/` (three instrumented mainnet nodes across regions — the empirical basis for ">90% synchronized" and ΔQ's π₁ ≈ 0.06; pre-testnet, business-as-usual only). Alongside: `constraint-model/` (verify/apply/reapply DAG scheduling of a voter's CPU — 12 MB EB makespan ≈ 3.74 s at 21.9% CPU utilization: **critical path binds, not cores**), `empirical-distributions/` (`block-edf.csv`/`tx-edf.csv`, the improved-ΔQ timing source), plus tx/UTxO/apply-reapply/bandwidth measurement corpora and `peer-topology` notebooks. These feed simulator inputs and CIP parameter justifications across the whole catalog.

### 11. Formal specification and trace verifier

**Deep dive:** [leios-simulation-model-catalog/11-formal-spec-trace-verifier.md](./leios-simulation-model-catalog/11-formal-spec-trace-verifier.md).

- **[ouroboros-leios-formal-spec](https://github.com/input-output-hk/ouroboros-leios-formal-spec)**: machine-checked Agda specification of Linear Leios (~4,000 lines, `--safe` modules), with **safety proofs** (common prefix, honest chain growth, existential chain quality — transfer theorems conditional on Praos base-chain properties, over a k-delayed diffusion functionality with categorically *arbitrary* adversarial nodes) and, as of **2026-09-15, progress proofs** (the node completes every slot, via the slot-upkeep obligation mechanism). Built on the categorical-crypto composable-process library; actively developed (Yves Hauser). [Rendered docs](https://leios.cardano-scaling.org/formal-spec/Leios.Linear.html).
- **[leios-trace-verifier](https://github.com/input-output-hk/ouroboros-leios/tree/main/leios-trace-verifier)** (with `leios-trace-hs`): a certified, decidable checker derived from the Agda spec (Andre Knispel, Yves Hauser; idea lineage from ARC Jolteon via Mauro Jaskelioff) that verifies whether an execution trace stays within the protocol envelope — deliberately *not* a deterministic reference implementation, so differently-scheduled implementations both pass. Two executables: file-based (batch or `--streaming`; simulator traces via `--conformance-events`) and **`-chain` live-node mode** (trace from stdin, leadership schedule and stake from a running node via cardano-api). Originally used to conformance-check the Rust and Haskell **simulators**; as of August 2026 it runs against **real testnet node logs**, including as a live network monitor on Ramsay Taylor's node (Taylor, Hauser, Javier Díaz; [Confluence blog](https://input-output.atlassian.net/wiki/spaces/NC/blog/2026/08/20/6219563009/Leios+Team+develops+safe+and+live+trace+verifier+for+protocol+conformance+testing)). Coverage recorded in `conformance-coverage.md`.

For this catalog's purposes the pair is the **faithfulness instrument**: it is how any simulator's protocol logic can be checked against the specification, and it spans spec → simulators → implementation.

- Mempool theory ↔ simulation ↔ measurement triad in `post-cip/` (hypergeometric overlap and poisoning slopes confirmed by the simulator; synchronization rules-of-thumb from instrumented mainnet nodes; π₁ ≈ 0.06 feeding the ΔQ model).
- Haskell vs leios-peernet alignment attempt (Feb 2025): ~2× latency discrepancy, early bottleneck in the Java model; documented in Slack, not in a repo.
- ❓🤖 **SCRUTINY**: still no cross-validation of "smol world," the Mininet test bed, or Piranha-as-simulator against sim-rs. The dives sharpened the natural first experiment: a **three-way transport calibration** — real CUBIC (Mininet bed, which ships unreported `topo-small-world*.json` inputs), simulated CUBIC (smol world), analytic CUBIC/Mathis (improved-ΔQ) — on matched topology and payload.

## Gaps and open questions

1. **AUEB report-series completion** — the simulator question is resolved (PeerNet, 2021-era reports; see entry 4); still open: obtain TECHREP2 (gossiping/peer sharing), the TECHREP experiment code, and the latency matrices missing from leios-peernet — via William Wolff (the 2026-04 code delivery) and Spyros Voulgaris.
2. **No unified faithfulness assessment** — this catalog records claims; a systematic comparison (same topology, same workload, across sim-rs / smol world / Mininet test bed / testnet measurement) has not been done. The dives identified the concrete first steps: the three-way transport calibration (cross-validation section above) and a **mempool-alignment reconciliation** — rows 5, 8b, and 10 hold three formulations of the same question (mechanistic ratchet, statistical π₁, hypergeometric overlap) over one measurement corpus, and row 12's node telemetry (LeiosTxCache funnel, mempool-hit rates) measures the same quantities on real nodes. The quantity-level correspondences and a concrete four-check experiment design are worked out in [leios-mempool-metrics-mapping.md](./leios-mempool-metrics-mapping.md).
3. **Private working corpora** — `leios-adversarial-tools` (Piranha) needs access granted; smol world's design docs, experiment driver, and reviewer exchange live in Marcin Wójtowicz's private environment; PR #880's BDP estimator is oracle-stubbed pending the probe implementation.
4. **Unmerged artifacts** — PR #880 (Mininet test bed) and PR #5424 (smol world) are both **draft** PRs on branches, #5424 with no review activity at all; if abandoned, this catalog's links rot and the work risks being lost.
5. **Unlocated referenced work** — Nicolas Henin's analysis, the TECHREP2 report, the Sept 2026 Linear Leios stability presentation slides, and the ATK attack-taxonomy document behind names like ATK-LeiosProtocolBurst (an ATK-002 analysis exists on Drive; the taxonomy index was not located).
6. **Spec-vs-CIP normativity** — no maintained correspondence between CIP-0164 prose and the Agda rules was found; which is normative on divergence is an open governance question (dive 11).
7. **The mempool is below the conformance floor** — the Agda spec models it as an abstract environment-fed list, so the trace verifier cannot adjudicate mempool-management behavior; any alignment study needs its own conformance notion (dive 11).
