The verifier is an instance of the generic trace verifier CategoricalCrypto.Machine.Trace for LinearLeios: the hint naming a step’s rule is its Action, and traces name inputs as TestInputs, mapped into the machine’s input by toRcvType. A StepWith a s i is a step from s on input i whose rule is a.

StepWith : Action → LeiosState → TestInput → Type
StepWith a s i = Σ[ x ∈ T.Step LinearLeios s (toRcvType i) ] getAction (T.derivation x) ≡ a

Error handling

Err-InputMismatch carries the real refutation ¬ StepWith σ s i. Deriving it requires inverting the transition’s input index toRcvType i, whose channel selections are opaque in categorical-crypto; the lemmas below therefore sit in an opaque unfolding _⊗₀_ block, where the selections reduce to constructor form and Agda can dismiss the impossible transition rules. The refutation is mediated by the input-channel selector: input-sound proves that every derivable step consumes the input constructor its action’s rule expects, so a selector mismatch refutes the step.

The premise-less Fetch rule reads its input through an output-typed channel selection, which nevertheless coincides with toRcvType (inj₂ (inj₂ (inj₁ FetchLdgI))) once the selections reduce; Fetch-step witnesses this inside the unfolding block, letting verifyStep' accept the pairing.
