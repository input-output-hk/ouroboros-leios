The tip changes while a certificate query is outstanding

The tip can move between a certificate query and its answer (Chain has no premises). The following trace moves it twice, making each outstanding answer stale, and shows that Base is discharged instead of getting stuck.

EB₃ and EB₄ are two distinct EBs whose voting windows have both already passed as of slot 200. 
12345678910111213141516
    EB₃ : EndorserBlock
    EB₃ = mkEB 190 fzero tt (EB , tt) (100 ∷ [])
 
    EB₄ : EndorserBlock
    EB₄ = mkEB 190 fzero tt (EB , tt) (200 ∷ [])
    RB₃ RB₄ : RankingBlock
    RB₃ = record { txsOrEbCert = inj₁ [] ; announcedEB = just (hash EB₃) }
    RB₄ = record { txsOrEbCert = inj₁ [] ; announcedEB = just (hash EB₄) }
    crt₃ : EBCert
    crt₃ = hash ⦃ hrb ⦄ RB₃
    s₂₀₀ : LeiosState
    s₂₀₀ = record s₀
             { slot = 200
             ; EBs' = (0 , EB₃) ∷ (0 , EB₄) ∷ []
             ; RBs  = [ RB₃ ]
             }
The EB role is settled first, as Base₂ requires; Base₂ then queries for a certificate on RB₃ (certRequest s₂₀₀ ≡ just EB₃), and the tip moves to RB₄ (Chain), so the answer for RB₃ is stale and Cert₃ re-queries for RB₄. The chain then becomes empty, so no certificate is called for, the answer for RB₄ is discarded and Cert₂ submits the RB without a certificate.
